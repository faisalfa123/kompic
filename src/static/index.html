🗺️ Alur Arsitektur Logika Sistem (Vertical Pipeline: Atas ke Bawah)

Diagram eksekusi mendalam dari deteksi file hingga pergantian atomik dan verifikasi cloud sync satu arah tanpa risiko kehilangan data.

🔍
1. Pemindaian Direktori Immich Upload
Scanner membaca rekursif /mnt/hdd1/immich/upload/upload, mengabaikan file sementara .tmp / .inprogress, dan mengekstrak daftar file baru yang belum tercatat di optimizer_state.json.
SCANNER
▼
🛡️
2. Evaluasi Perlindungan (Suhu & Jadwal)
Thermal Check: Jika CPU ≥ 75°C, supervisor masuk mode THROTTLED/PAUSE hingga suhu mendingin ≤ 65°C.
Schedule Check: Pada mode NORMAL, proses hanya berjalan di jendela jam hemat (01:00 - 06:00). Pada mode FORCE, jadwal di-bypass seketika.
GATEKEEPER
▼
📍
3. Ekstraksi Utuh Metadata & Apple Live Photo Pair
Membaca EXIF asli via exiftool: Koordinat GPS (Latitude, Longitude, Altitude), Kamera/Lensa, Tanggal Asli (DateTimeOriginal).
Khusus Apple Live Photo: Mengunci tag ContentIdentifier dan MediaGroupUUID agar sinkronisasi foto-video gerak tetap menyatu di Immich.
METADATA GUARD
▼
⚡ 4. Aturan Penjadwalan Konkurensi & Mesin Kompresi (Mutual Exclusion)
🎬 Video Solo Worker (Maks 1 Video)
FFmpeg libx265 ultrafast, CRF 26, Max 1080p, 1-thread (stabilisasi ARM64). Aturan Ketat: Saat video dikerjakan, foto mandiri ditahan (0 foto) untuk menjaga suhu & RAM.
📸 Photo Batch Worker (3 Foto Sekaligus)
Mengerjakan 3 foto sekaligus secara paralel (0 video). Mengurangi dimensi ke maks 2560px dan kompresi kualitas 82 (Lossless chroma subsampling 4:4:4).
✨ Live Photo Pair (Prioritas 2 Worker)
Pengecualian khusus: Pasangan Live Photo (1 Foto + 1 Video pendamping) diprioritaskan dan dikerjakan bersamaan (2 worker) dengan preservasi tag ContentIdentifier.
▼
💉
5. Re-injeksi Metadata & Verifikasi Validasi Nol Kehilangan GPS
ExifTool menyuntikkan kembali seluruh metadata dari file asli ke file hasil kompresi sementara (.opt.tmp).
Zero GPS Loss Guard: Jika file asli memiliki koordinat GPS tetapi file sementara gagal memuat koordinat GPS, proses kompresi seketika DIBATALKAN dan file asli dipertahankan 100%.
GPS VALIDATOR
▼
⚖️ 6. Evaluasi Ukuran: Apakah Hasil Lebih Hemat?
✓ LEBIH HEMAT (CompSize < OrigSize)
Atomic Replace: File asli digantikan secara instan dengan os.Rename. Hemat ruang dicatat dan status file menjadi SUCCESS.
✗ BOROS (CompSize ≥ OrigSize)
Skip Guard: File sementara .opt.tmp dihapus. File asli dipertahankan utuh tanpa sentuhan. Status dicatat sebagai SKIPPED.
▼

7. Sinkronisasi Cloud Satu Arah (Rclone MEGA: /YYYY/MM/DD/)
File yang berhasil diproses otomatis dijadwalkan ke antrian Rclone.
• Hierarki Waktu: Disimpan ke remote folder berdasarkan tanggal pengambilan media (contoh: mega:ImmichBackup/2026/10/22/filename.jpg).
• Sinkronisasi Hapus: Jika suatu file dihapus di server lokal Immich, mesin otomatis menghapus file pasangannya di MEGA cloud untuk membebaskan kuota.
ONE-WAY SYNC

🛠️ Arsitektur Mandiri ODROID-C2 (Golang Native)

  • Ringan Tanpa Python: Seluruh backend berjalan sebagai binary mandiri Go dengan konsumsi memori hanya ~10–15 MB RAM (menghindari OOM crash pada RAM 2GB).
  • Preservasi Geolokasi (GPS) Terjamin: Koordinat lokasi foto & video (EXIF GPS IFD, QuickTime Keys, UserData) dipreservasi utuh dengan verifikasi otomatis. Jika file asli memiliki lokasi namun hasil kompresi gagal menyalinnya, sistem otomatis membatalkan penggantian (Zero GPS Loss Protection).
  • Preservasi Live Photos: Seluruh metadata iPhone (ContentIdentifier, MediaGroupUUID, QuickTime maker tags) disalin utuh via exiftool.
  • Atomic Replace (Skip Boros): File hasil kompresi hanya akan menggantikan file asli jika ukurannya terbukti lebih kecil. Jika hasil lebih besar, file asli tetap utuh dan ditandai Skip (Boros).
  • Flowchart Real-Life: Tab Flowchart Monitor menyala secara real-time mengikuti node proses yang sedang dieksekusi CPU ODROID-C2.
  • Auto-Run Tiap Boot: Telah terintegrasi dengan service systemd immich-optimizer.service sehingga otomatis aktif tanpa perlu terminal.

⚡ Panduan Service Auto-Run Systemd

  • Cek Status Service: systemctl status immich-optimizer.service
  • Restart Service: systemctl restart immich-optimizer.service
  • Pantau Live Logs: journalctl -u immich-optimizer.service -f
  • Installer Otomatis: Jalankan ./install-service.sh di folder server.
